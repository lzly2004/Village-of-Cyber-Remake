# WEB-036 浏览器累计战绩存储

基线main@d04b2de。仅实现持久存储、终局入账状态与错误重试，不提前实现037统计页面；不改Java、规则、接口、随机源、Replay/会话/音频格式，不读取服务端内存战绩。

## 入账和信息边界

RecordSettlement仅在原finished门槛（FINISHED且当前事件已确认完毕）、非busy/uncertain/Replay播放时触发。completedRecord只捕获sessionId、公开configuration/result，拒绝NONE/未知配役/未知胜负；不读取玩家真实身份或技能。中途退出不计，Replay播放/导入不计；终局恢复、同步、重复渲染和多标签均按同一对局去重。已成功入账的数据独立于新游客局；新建对局不清历史。旧版网页已结束而从未入账、且会话已失效的对局不猜测补记；桌面文件不自动导入战绩。

## 数据与事务

累计范围是当前origin，不以sessionId划分用户；sessionId仅标识一局用于去重。同origin独立IndexedDB vocr.records.v1/version1，results存储使用自增sequence确定提交顺序，唯一id索引是规范化UUID的SHA-256；仅存id/configuration/result/sequence，不保存原始游客凭据、人物/职业、Replay或服务器路径。此hash是去重标识而非身份保密/可信排行。七配役顺序取peiyi；两种ID不是Replay内容hash，不受Replay删除或重复导入影响。

每次记录在单readwrite事务内校验既有账本、查询唯一id、添加新项；同id相同结果返回duplicate，不更新sequence；冲突RESULT_CONFLICT，坏项INVALID_HISTORY，事务中止且不重建/覆盖旧数据。仅oncomplete报告成功，请求成功但事务中止不能计成功。跨标签RW事务串行，sequence按提交顺序，读也在一致事务内cursor聚合。先复制入账意图再异步hash，晚到不会把结果写成另一局。无跨设备/跨origin/服务器同步；库无法打开、blocked、15秒超时、配额和hash不可用均明确诊断，不静默改用localStorage或内存成功，不重试风暴；用户显式重试仍幂等。

## 与桌面计数对齐

read()从账本按sequence构造GameRecord形状：索引0空，1—7对应原配役；每个胜负计一局，VILLAGE_WIN才算胜率/连胜的胜，狼/狐胜会中断该配役连胜。不同配役互不打断；totalMaxStreak是七配役历史最大值，不是跨配役连续胜场。胜率为村胜/局数×100，五位HALF_UP，整数BigInt计算避免浮点舍入偏差。桌面遗留wincnt未被update更新，保持0不重新解释；version2是聚合对象形状，独立IDB版本仍为1，不承诺桌面战绩文件导入/导出兼容。

同一浏览器配置的共用者可见历史；换浏览器/无痕/清站点数据/驱逐/换域或协议端口不自动迁移。失败时日文诊断、显式重试，不禁用对局操作。当前无自动清理/截断；追加校验与read聚合是O(n)，长期规模/配额/延迟归047，不能据几局通过宣称无限容量或永久保存。统计页面和正式固定脚本展示对照归037；A11未全面放行。
