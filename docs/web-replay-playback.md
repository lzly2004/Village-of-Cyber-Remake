范围：从032已校验的本地库选择录画，以桌面固定样本浏览日期、人物头像/CO与死亡标记、人数/吊绳；复用027/028的单一BGM通道。信息/票型/技能历史归034，文件导入导出/历史迁移归035。不把rawRecords冒充逐条台词动画，不改文件/数据库格式、核心/HTTP、随机源或战绩。日文化/像素截图/DPI/听审的正式门槛不因本轮放行。

## 桌面来源与差异

已核对局内VoteInfoRenderer/UIHelpers，以及ReplayPlayerHandler相关调用与030契约；不统一两条路径的历史偏移。

- 桌面浏览器进入时replayDay=1，但handler会钳到2，再钳到totalDays；网页默认min(2,totalDays)，导航在此起点和末日禁用越界，提供日期下拉。单日文件保留第1日。网页不照抄桌面day=2分支在末日仍显示无效“下一日”的交互。
- `getSnapshot(day)`先精确dayNumber，再按day-1数组位置旧回退。网页保持该选择，但任何位置替代明确显示SNAPSHOT_INDEX_FALLBACK及真实来源日；缺数据为SNAPSHOT_MISSING，不造人数。头像优先day+1（包括该方法的旧位置回退），完全缺失再取当前日；内日缺次日明确AVATAR_NEXT_DAY_MISSING，末日缺下一日为正常回到当日。
- 头像来源快照中的actualRole直接按ImageNames.characterRolePortrait选色，**死者仍为职业彩色**，不同于025终局灰头像；死亡印严格deathDay>0 && deathDay<选中日。CO图严格claimedRole 1..5且comingOutDay>0，不额外增加<=当前日判断：固定样本第2日会显示第3日快照记录的CO。界面标注人物/CO来源日，避免当成正在进行中的公开投影。
- 数据面板取当前日快照aliveCount，死亡数=首快照人数-aliveCount，吊绳为alive>1时整数(alive-1)/2，否则0，不按头像死亡数重新计数。玩家索引与人物外观序号分开，保留数组顺序/两行布局；44人时本地可键盘聚焦/滚动，不卡掉末项。
- UiImage.REPLAY_BACKGROUND为PVBG.png；职业头像、CO/死亡标记复用022/023/025既有清单，缺图/越界CO顺位显示既有诊断，不造替代职业或重建素材。原桌面的绝对像素布局改为有界原生DOM两行/滚动，正式视觉对照仍属A07/046；票型和技能图本轮不提前接入。

## 状态与资源边界

ReplayEntry为轻量入口，仅显式列表/保存才加载ReplayLibrary chunk；不开库、不取录像、不预载人物资源。库按032全量校验后复制所选录像到播放器的独立内存快照；打开过程中他处删除不改变已打开记录，关闭后显式重读列表反映删除。播放器不写IndexedDB/sessionStorage，不调用游戏命令/Replay读取接口，不把录像恢复为对局。

播放器为标明“役職を含む録画閲覧”的原生modal dialog；Esc/关闭返回列表并恢复按钮焦点，底层活局保持原游标/事件/预约，刷新仍恢复活局且播放器重新关闭，播放日期不新增存储。校验失败明确INVALID_REPLAY；缺日期/图标不妨碍导航/关闭。文本插值，无v-html。角色真职只来自已保存终局录像，不能借播放器读取在途会话。

库的15s加载故障可关闭；若代码晚到，已超时/更换会话的初始保存意图取消，不能忽然写入或保存新局。明确失败后需再操作，不自动重放。

Replay BGM映射BgmTrack.REPLAY_PLAYER，仍是原单个HTMLAudioElement/AudioContext/Gain、Blob校验与释放机制；没有新context/自动解锁/预取。已启用音乐时随场景切换；未启用时须在弹窗按钮同步手势启用。进入/退出清旧场景音效队列并保留当前CLICK，播放期间不排入活局音效；切日不重启曲目。关闭后回到当前活局/大厅的场景曲，不重新启用已停止/后台暂停的音频；显式选过的日间曲在经历Replay场景后按场景默认曲返回，跨天选曲计数不重置。失败诊断在弹窗内可见，手动重试不妨碍日次浏览，物理输出/听审/无缝循环仍未验收。
