# WF-008 用户试玩补修：夜晚与晨间转场

基线为 PR #12 首审 head `300a806`。用户指出处刑之后直接显示死亡结果；核对桌面后确认缺少本地场景，已获用户明确批准在本 PR 补齐。此项不等于 WEB-050 外观改造，不改变 Java、规则、API、权威事件或存档格式。

## 来源与呈现契约

| 本地呈现 | 桌面来源 | Web 行为 |
|---|---|---|
| 夜晚纯背景 | `GameSceneHandler.renderNight`、`UiImage.NIGHT_BACKGROUND`、`UIConstants.NIGHT_SCREEN_DURATION_MS` | 当前公开夜结果组入口显示夜背景；解码发布后播放 NIGHTFALL 并停留 7000ms，不挂载结果台词或人物 |
| 晨间纯背景 | `renderDay`、`GAME_SETUP_DIALOGUE_BACKGROUND`、`HOWL_TRANSITION_MS` | 夜晚结束才请求并发布晨间背景；发布后 WOLF_HOWL、2500ms，无人物或结果台词 |
| 日数与本地继续 | `GameStrings.DAY_START_FORMAT`、`TYPEWRITER_DELAY_MS` | 每字50ms；完成后显式“続きを読む”只结束本地场景，不确认事件 |
| 夜结果 | `DialogueDayDeathHandler` 与既有025两帧映射 | 本地继续后才显示当前公开死亡或平安事件；原 next-event 才推进已读游标 |
| 执行后直接终局 | `DialogueChuxingHandler` → `renderNight` | 当前公开 SETTLEMENT 紧随 EXECUTION 时只显示7秒夜晚，之后显示既有结算；不先读未来胜负决定是否播放晨间 |

同一个连续 NIGHT_RESULT 组只显示一次入口；当前组的绝对游标及会话组成完成键。同局公开刷新不重复已完成本地场景，完整页面重载重新播放当前组入口，不修改已确认游标。减少动态效果保留两张静态背景及7000/2500ms顺序，日数直接完整显示，死亡沿025直接后帧。

计时只从当前背景解码并发布开始；上一阶段未结束不预取下一背景。损图取消计时并显示有限诊断，允许显式本地退出，不消费当前事件。单张转场背景若一直不就绪，Web额外以15000ms等待上限给出NIGHT_IMAGE_TIMEOUT；该加载保护不属于桌面7000/2500ms展示时长，晚到不能恢复已退出场景。历史前缀缺失诊断、不猜测另一个夜晚，保持原事件可读；补读恢复仍是原有只读请求。同步不确定与卸载取消旧回调，版本号拒绝晚到结果。声音未启用、后台停止、之后启用均不补播过去场景的声音。

## 测试边界与旧测试适配

新增 `night-day.spec.js` 直接使用 Playwright 原始 fixture，逐项核对6999/7000、2499/2500、日数键盘继续、同夜多人、执行终局、刷新、损图、图片晚到、同步不确定、前缀缺失、挂起超时及减少动态效果。首次缺模块失败、虚拟时钟夹具失败及修正日志保留；集中单测时误改RegExp标识符的失败也保留并修正，仅测试搬移错误；没有通过改生产校验消除夹具问题。

原业务/几何旅程显式改用 `test-fixtures/presentation-test.js`：安装测试时钟，遇到本地场景时按生产时长推进展示并只点击 day-start-continue，再继续原断言。它不点击 next-event、不投票、不替代本地时序专项；drain 将本地呈现单列为状态，不把按钮暂时缺席当成收敛。多浏览器页须单独准备该 fixture。原有角色、源映射、信息边界、游标、票型和几何断言保留；没有扩大超时、改预算或加入生产测试开关。

真实媒体音频测试仍用实际时间等待两段背景，检查提前结束 NIGHTFALL 不提前触发狼嚎、局部继续前不请求死亡/平安音效。原帧重看不重复效果、混音信号/静音、CLICK 一次一请求等断言保留。物理听审仍由用户提供，不由自动化信号替代。
