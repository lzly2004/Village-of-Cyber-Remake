## 目标与已确认的缺口

目标是关键界面看起来与桌面版一致，包括整体结构、信息位置、按钮布局、素材和字体效果，不能仅以“同源素材/舞台坐标一致”判为完成。当前Web侧栏、顶栏、TEXT EDITION标签和浏览器文档流是临时实现，不是最终视觉基线。

源码锚点：`UI.java`使用不可调整大小的JFrame，setSize为1280×720；`UIConstants.java`指定Takao Mincho及按钮20/投票24/对话26/标题50等字号；`StartSceneHandler.java`使用原版标题/菜单素材与坐标。Web的`App.vue`、`style.css`目前使用侧栏网格、顶栏和无衬线字体。JFrame外框尺寸不等于实测客户区尺寸：基线采集须分别记录窗口装饰、客户区和设备缩放，不能把浏览器1280×720截图直接当作已对齐。

## 实施前必须固化的基线

在050开始时，Coder先启动当前桌面程序，记录提交、系统/Java、实际字体及回退、客户区尺寸、DPI和缩放，采集下表成对场景。使用既有隔离样本/确定性路线，禁止修改用户录像与战绩。字体声明不证明实际字体已安装；当前src/main中未找到字体文件。核对实际字体来源与可用性后确定Web实现，若需要替代字体，先向用户展示并确认差异，不用未确认的替代字体宣称一致。

### 字体选型与预算前置门

- 核对桌面实际解析的字体、具体发行文件/版本、来源和许可说明，区分本机使用与随Web包分发/子集化；不能由字体名称推断许可，更不预先认定Takao不可分发。若只用系统回退，须记录不同浏览器/系统的实际结果；仅写CSS字体名不能声称跨设备一致。
- 在桌面实际字体、可分发的候选字体与系统回退之间，提交样张和成本对比；说明完整/子集文件、字符覆盖及回退、加载页面/时机和缓存。仅标题用明朝体不是默认可接受的对齐方案，必须展示正文差异供用户确认。
- 子集覆盖日文假名/汉字、ä/ü、角色名、台词、诊断、动态信息与导入Replay中的未知字符；缺字必须有可读回退，不删正文凑子集。测试字体加载成功、失败/超时、字体替换后的换行与控件位置，选型时固定font-display及必要预载/加载顺序，量测加载前/后与失败回退的几何、FOIT/FOUT和布局偏移，避免不可见文字或迟后布局把按钮挤出。传输量测须等待当前页必需字体完成或明确失败，并覆盖后续字体请求，不能在迟后加载之前截断计量来过门。
- `asset-tests/images.spec.js`实际断言是冷大厅≤1.5MiB、首局新增≤3MiB；134,994B/397,068B等是历史实测值，不是固定上限。现有resource transfer统计会计入网络字体；新增字体计入所在页面必要传输，不能按音频例外排除。所有字体/备用格式计入静态100MiB；现有预留1MiB不是未审批的字体专用额度，050先列分组账本，超过预留或需挪组额度须明确批准。
- 用户确认字体方案前，提供文件大小/压缩传输、冷/暖首页及首局增量、静态合计、解码/布局影响与字符覆盖。保持现有限额；若仍需调整，提交旧值→建议值、原因及受影响断言/Q03/047口径，获批后同步预算文档和门禁。不得因更换外观直接提高阈值，或靠隐藏/延后必需文字绕开预算。047另量测最终字体加载/内存/流量，050的单机实测不代替容量验收。

### 剩余中文文案日文化的实施范围

050负责实际替换，046/049负责最终语言复检，不能把缺少实现的工作继续挂在验收门。实施时基于[018来源目录](web-japanese-display-catalog.md)、[029剩余语言清单](web-japanese-help.md)及截至043和WF-008已实现的提示；后续044/045新增提示由各任务同步采用日文并补入清单，046/049统验。建立“文件/入口/当前文本/来源或新增译文/日文定稿/测试/例外”清单，覆盖结构标题、阶段/阅读/名单/技能/投票提示、操作/空态、存储/网络/凭据/容量/恢复/导入导出错误、视觉/音频/资源诊断及可访问名称。不能只翻当前截图可见的正常路径。title/tooltip/placeholder是Web可控文字，应纳入清单；浏览器文件选择默认按钮、原生表单校验消息另列“浏览器原生文案”，记录浏览器语言与可控边界，不以HTML lang保证其全为日文，也不修改用户系统语言来过验收。

有桌面日文依据的显示文字直接复用并对照；Web新增提示、源中文帮助/混用常量须作为翻译提案校对，不能冒充恢复出的原文。原始台词JSON、帮助/图片原件、协议键、日志/文件格式不因翻译而改写；需要在Web显示层处理的混用文字/内嵌图片文字须列具体方案并纳入成对截图。原文帮助、历史引用、用户导入内容等保留原文的部分逐项列为例外，标明语言/来源，日文导览与解释保持可读，不伪造原作者发言。

错误码及其有限分类、重试/取消/保存语义保持，译文仍明确“显示诊断，非日文原台词”，不得隐藏故障或变更信息门槛。日文化后同步可见文本、aria名称、lang标注和定位期望；中文汉字与日文汉字重叠，不能用“检测到汉字”当作残留中文检查或翻译正确性证明。按清单覆盖正常/异常/辅助文本与人工日语校对，已批准的原文例外单列。A06须在实现完成及046/049复检后再评估，不以静态扫描或全部测试绿灯关闭。

## 可判定的完成标准

1. 完成口径为“桌面关键画面的结构、信息位置、字体效果一致，加经用户确认的Web特有差异清单”。每个基线场景均有同状态、同逻辑尺寸的桌面/Web对照图，以及区域坐标、尺寸、层级、字体实测记录。先去除未经批准的Web额外外壳；任何保留或新增区块逐项注明理由并取得用户认可。不能只截舞台而忽略外围操作区。差异清单至少包含场景/控件、桌面对应、必要性、布局/文案、信息/操作影响、受影响A/Q行及理由、用户确认；例如游客恢复关联A12/Q04、本地Replay库与文件交换关联A09/A10。战绩和Replay本身已有桌面对应，不能整页以“Web独有”为由免对齐，差异应限于游客恢复、浏览器本地库/整库交换、音频手势解锁等具体能力。
2. 基线确认时逐区域固定坐标/尺寸与可接受偏差，字体抗锯齿等环境差异单列；未约定偏差前不得自行以“差不多”放行，也不以整图像素阈值替代文字/控件完整性检查。视觉回归基线须经用户确认；后续变更不得自动刷新黄金图掩盖差异。
3. 1280×720逻辑基准下检查整体构成；1024/800/768窗口及125%/150%浏览器缩放作为适配检查，明确允许的滚动路径。长文本、多人物、最后一个候补和确认按钮必须可见或可达，不以裁切/隐藏来凑一屏。046对最终外观执行正式浏览器/DPI/辅助技术验收。
4. 纯文本台词、换行/Unicode、键盘焦点与可访问名称继续保留。公开投影、真实身份揭晓门槛、事件顺序/确认游标、刷新恢复、CO中断、随机源、协议和存储格式不变；素材清单可枚举不能作为保密层。
5. 仅替换与已批准新布局矛盾的布局断言；保留业务、信息边界、反裁切、末项可达和无副作用断言。实际查看截图后再交付，截图附SHA-256及环境记录；不把不能读图的CR结论称为独立视觉核验。

按AGENTS执行前端单测、生产构建、相关视觉/浏览器回归；共享结构变化追加默认回归与相关gate，并使用最终源码的oracle。不因新增计划提前运行本机Java全量。首审交接包明确基线/目标、成对截图与哈希、变更边界、实际验证和未验证项，由用户转独立CR；视觉部分须由能读图的审查者或用户确认。
