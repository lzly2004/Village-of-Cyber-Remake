## 目标与已确认的缺口

目标是关键界面看起来与桌面版一致，包括整体结构、信息位置、按钮布局、素材和字体效果，不能仅以“同源素材/舞台坐标一致”判为完成。当前Web侧栏、顶栏、TEXT EDITION标签和浏览器文档流是临时实现，不是最终视觉基线。

源码锚点：`UI.java`使用不可调整大小的JFrame，setSize为1280×720；`UIConstants.java`指定Takao Mincho及按钮20/投票24/对话26/标题50等字号；`StartSceneHandler.java`使用原版标题/菜单素材与坐标。Web的`App.vue`、`style.css`目前使用侧栏网格、顶栏和无衬线字体。JFrame外框尺寸不等于实测客户区尺寸：基线采集须分别记录窗口装饰、客户区和设备缩放，不能把浏览器1280×720截图直接当作已对齐。

## 实施前必须固化的基线

在050开始时，Coder先启动当前桌面程序，记录提交、系统/Java、实际字体及回退、客户区尺寸、DPI和缩放，采集下表成对场景。使用既有隔离样本/确定性路线，禁止修改用户录像与战绩。字体声明不证明实际字体已安装；当前src/main中未找到字体文件。核对实际字体来源与可用性后确定Web实现，若需要替代字体，先向用户展示并确认差异，不用未确认的替代字体宣称一致。

## 可判定的完成标准

1. 每个基线场景均有同状态、同逻辑尺寸的桌面/Web对照图，以及区域坐标、尺寸、层级、字体实测记录。先去除未经批准的Web额外外壳；任何保留或新增区块逐项注明理由并取得用户认可。不能只截舞台而忽略外围操作区。
2. 基线确认时逐区域固定坐标/尺寸与可接受偏差，字体抗锯齿等环境差异单列；未约定偏差前不得自行以“差不多”放行，也不以整图像素阈值替代文字/控件完整性检查。视觉回归基线须经用户确认；后续变更不得自动刷新黄金图掩盖差异。
3. 1280×720逻辑基准下检查整体构成；1024/800/768窗口及125%/150%浏览器缩放作为适配检查，明确允许的滚动路径。长文本、多人物、最后一个候补和确认按钮必须可见或可达，不以裁切/隐藏来凑一屏。046对最终外观执行正式浏览器/DPI/辅助技术验收。
4. 纯文本台词、换行/Unicode、键盘焦点与可访问名称继续保留。公开投影、真实身份揭晓门槛、事件顺序/确认游标、刷新恢复、CO中断、随机源、协议和存储格式不变；素材清单可枚举不能作为保密层。
5. 仅替换与已批准新布局矛盾的布局断言；保留业务、信息边界、反裁切、末项可达和无副作用断言。实际查看截图后再交付，截图附SHA-256及环境记录；不把不能读图的CR结论称为独立视觉核验。

按AGENTS执行前端单测、生产构建、相关视觉/浏览器回归；共享结构变化追加默认回归与相关gate，并使用最终源码的oracle。不因新增计划提前运行本机Java全量。首审交接包明确基线/目标、成对截图与哈希、变更边界、实际验证和未验证项，由用户转独立CR；视觉部分须由能读图的审查者或用户确认。
