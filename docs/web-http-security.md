## 执行前限额

所有参数为进程内代码常量，测试构造器可注入独立策略与单调时钟，不新增CLI、环境变量、账号、Cookie或生产依赖。`GuestRequestLimits.Policy.production()`为唯一生产默认：

| 层 | 生产值 | 计数及恢复 |
|---|---|---|
| 全部进入Javalin的HTTP请求 | 250次/秒、突发500 | 未知路径/畸形请求也消耗；进程共享令牌桶，不依据来源IP或代理头分配无限键 |
| 创建POST空路径 | 100次/分钟、突发20 | 解析body及构造GameSession前消耗；删除/失败不退还频率令牌，不靠创建→删除绕过 |
| 已存在有效会话的GET/游戏命令 | 100次/秒、突发200 | 每个Entry独立桶；未知UUID不新建桶；DELETE仍受全局限额，不持有会话借用，不阻碍主动释放 |
| Replay读取 | 每局8次/分钟、突发8 | 与普通会话桶叠加；业务拒绝也计数，不做未获授权内容的预取或缓存 |
| 全局在途应用处理 | 8 | 无队列tryAcquire，包含body解析、执行和响应序列化，到after归还 |
| 在途创建 / Replay处理 | 各2 | 与全局8叠加；Replay名额持有至整个HTTP handler结束，覆盖借用归还后的重建与序列化 |
| 单局同时借用 | 2 | 在进入GameSession前拒绝更多借用，不排队积累同局规则操作 |

成本名额绑定到已注册的POST创建/GET Replay endpoint wrapper，不用原始URI猜测路由；尾斜杠等被路由器接受的别名不能绕过。固定Javalin 7.2.3的HEAD不执行GET业务处理，实测同一非法游标HEAD200空体而GET400；如果未来框架将HEAD调入GET，注册handler包装仍先执行。框架回调语义参考[Javalin官方文档](https://javalin.io/documentation#handlers)，本机固定依赖的编译及实际HTTP断言为当轮依据。

频率桶按`System.nanoTime()`经过时间补充，最多积到突发容量；单调计数环绕不改变语义，墙钟/时区不参与。拒绝不会重置桶或凭据TTL。桶只存进程2个及每个存续Entry2个，Entry随039回收；不记录原始IP、URL、凭据或body，不创建按任意输入增长的Map。频率令牌不因请求失败退还；并发名额在异常路径归还且close幂等。

拒绝统一`429 REQUEST_LIMIT`及正整数秒`Retry-After`，消息有界、不回显输入；限额均在游戏操作前执行，因此已知status/code组合可证明该次操作未执行。并发拒绝的1秒是建议间隔，不保证一秒后名额已空闲；客户端不自动等待/重发。写/创建显示明确拒绝并保持原凭据/游标；读取被拒保留旧状态且锁决策，只允许用户稍后显式同步，不走C=0回退。未知429、代理HTML或错误code沿用040不确定处理，不伪装成执行前拒绝。

这些是初始保护策略，**不是100人吞吐/SLA或抗DDoS证明**。进程共享桶没有按人公平保证，恶意请求可消耗全局预算；同一能力的持有人共享单局预算。服务重启清桶，其他进程不共享，不能当作分布式限流。043同源HTTPS/可信代理及047并发、256MiB堆、挂起body/响应、8MiB终局Replay重复读取实测仍需完成。应用名额不包含底层socket/连接队列，after不等于客户端已收完网络字节；不声称硬连接数/端到端请求墙钟上限。保留现有JSON写路径读取body时的16KiB上限及100会话容量，不用不安全中断正在执行的规则请求来伪造超时回收。

## 与039的组合

只在全局/创建名额、频率及单局名额均接受后才进入原命令。`withSession`内应用层400/409仍在finally归还借用并续空闲期，这是039既定语义；执行前429不进入该finally，不续期。24小时硬上限任何成功访问、业务拒绝或限流均不能延长；到期不接受新借用，在途请求按039完成后关闭。不新增心跳/轮询，不改变本地逐条确认及终局揭晓。
