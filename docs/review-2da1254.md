## WEB-006 实现

- 新增 POST `/{id}/claims/by-role`，直接解析 AskClaimByRoleCommand 并复用 GameSession.requestClaims；不复制 CO 规则，不新增生产依赖，不改变已有 API 形状或存储格式。
- 前端按钮从权威 claimInquiry.roles 渲染；新文案取原版日文职业名。仅在 canDecide 且 role 仍合法时提交最新 revision；busy/uncertain/未读事件期间禁用，终局合法角色为空时不显示入口。
- 成功响应走共用 accept/游标补读，公开 CO 状态由服务快照恢复；不存本地“已问职业”状态。409、失效会话和响应丢失沿用同步而非自动重放，未顺带实现 WEB-040 的全部错误分类。
- HTTP：七配役各顺序询问五种职业，与同种子直连完整更新逐次一致，响应与同游标 GET 重读一致，另一个会话不受影响，全程使用序列化门禁。缺失/null/非法/非可询问职业、未知字段、坏 JSON/版本、并发旧版本及终局拒绝均有断言。
- 浏览器：固定种子通常村实际询问狩人并产生新 CO 发言，覆盖未读禁用、刷新恢复、409 不重放、已执行但响应丢失后同步。既有完整终局测试增加 CO 入口消失断言；未把投票 CO 中断测试改成新询问路径，保持两者独立覆盖。
