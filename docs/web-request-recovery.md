# WEB-040：请求分类、窄游标恢复与不确定操作

本轮只改前端请求/会话控制和对应测试，不改Java、规则、随机源、接口字段、会话存储形状、Replay或战绩格式。v1服务端契约仍见[API草案§4/5](web-api-v1-draft.md)。039首审及主线核验处置见[review-39ff007](review-39ff007.md)。完整日文化仍归050；本轮提示按现有界面语境明确区分读与写，不冒充桌面原文。

## 分类与操作范围

`requestRecovery.js`按ApiError实例、状态、业务码和操作范围分类，不按状态区间猜测。`api.js`保留单请求15秒AbortController，超时覆盖响应体读取；没有重试循环。只有业务JSON媒体类型才解析为业务错误；HTML内即使恰有已知code也不参与控制流。成功状态须符合现有契约：创建201、释放204、其余200；非契约成功状态不能确认写入或释放。

| 组合 | 范围 | 客户端动作 |
|---|---|---|
| 404 GAME_NOT_FOUND | 已有会话的读/写/释放 | 清当前能力凭据及确认游标；保留Replay/战绩和无关键 |
| 400 INVALID_REQUEST | 当前会话GET | 仅当前游标>0时补读一次C=0；不是其他GET/其他路由的通用策略 |
| 409 STALE_REVISION / INVALID_STATE | 对局写 | 自动GET当前游标同步一次，不重放原命令；同步失败保持写禁用 |
| 400 INVALID_REQUEST / 413 HTTP_ERROR / 415 JSON_REQUIRED | 写或创建 | 确定拒绝，显示文本，不重试、不重置游标；并不证明其他页面没有写入 |
| 503 SESSION_LIMIT | 仅创建 | 明确未创建新局、用户手动再试；不是任意503的语义，也不把命令路由同码当容量拒绝 |
| 其他状态/未知code/坏JSON/HTML/网络/超时/坏成功窗口 | 读 | 保留凭据、确认游标和上次可用投影，标明权威状态未确认并禁用决策；不描述成“GET执行了投票” |
| 同上 | 已有会话的写/释放 | 结果不确定，禁用后续决策，等用户显式再同期；不自动重发、重复释放或只改revision重试 |
| 同上 | 创建 | 无id时明确可能已创建但无法找回，允许用户主动重开、孤儿局由039回收；已收到合法id但update坏时保留id/C=0供显式GET恢复 |

错误message只作纯文本提示，不参与分类。不新增429可信限流码，041另行定稿。记录/Replay恢复候选仍为PROPOSED，不借040执行坏库删除或自动修复。

## 游标与状态提交

1. GET读取失败不改变本地C；仅可信400 INVALID_REQUEST触发至多一次C=0补读。C原已为0时不重复同读。
2. 补读成功且窗口有效后才提交C=0；补读仍失败则保留原C，不循环、不跳过事件。重试按钮是新的显式读取，不是自动重放。
3. 成功投影在替换前核对最小外壳、业务阶段/版本、安全整数游标、原始/展示事件数组及窗口长度、页面操作集合；当前GET窗口必须从请求C开始。错误的200 JSON不能抹掉旧投影。这不是所有嵌套DTO的完整schema重实现；人物/公开信息/素材异常仍由已有诊断负责。
4. 命令窗口若无法覆盖已确认C，先GET补读；GET失败不会接受跳跃窗口。投票响应须含布尔voteCompleted，未知外壳不能冒充成功CO中断。
5. busy同步锁继续阻止重复在途操作；本地确认不发HTTP、不直接更新服务器revision。相同能力凭据的两个页面共享一局，各自保留确认游标；旧revision冲突只同步，草稿由已有update watcher清空，用户重新决策。
6. 读取失败锁住决策是避免继续使用过时合法动作；不会清除已存在的写不确定状态。只有可信同步成功才能解除，或可信GAME_NOT_FOUND结束该局。

## 无后台推进复核

当前仍无SSE、轮询或自动重发对局命令。`nextEvent`只推进本标签页确认前缀，服务器读不消费事件；其他页面可以主动写入，所以旧页面只在显式同步/命令冲突后看到新权威状态，不承诺实时多页同步。展示立绘缺前缀的补读仍是受版本/会话校验的只读辅助请求，不更新对局权威状态；与F2的失败恢复补读分开计量。039定时器只回收过期会话，不推进游戏。新增后台写入/推送需要独立契约与授权，不能沿用本轮假设。
