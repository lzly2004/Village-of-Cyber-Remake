## 结论与决策门

1. **公开CO的技能历史确实可见**：占卜/灵能带黑白球、护卫只列目标；包括仍保留CO的死亡行动者，也可能追溯其CO前的历史。不能仅按“结果是私有字段”全部禁止，也不能据此开放未CO者的结果。
2. **怀疑面板确实存在，但公开的是派生摘要**：当前日、存活观察者的前三目标及相邻强弱符号；原始分数/完整矩阵仍不可公开。
3. **现有运行中HTTP投影的精确夜间死因超出桌面公开范围**。`PlayerViewProjector`原样返回`getDeathReason`，而局内事件和图标将咬杀/夜间猫咒/夜间后追/咒杀合并。这不是“前端不展示就安全”，也不是白名单结构测试能发现的秘密值问题。
4. 建议在WEB-014实现安全报告/怀疑摘要时，同时收紧公开死因。因为涉及已存在的`VisiblePlayer.deathReason`语义/枚举及v1草案兼容规则，**须用户明确批准后才能修改**；WEB-014暂置BLOCKED，不跳过依赖执行015及后续。推荐修订未正式上线的v1公开分类，运行中统一`NIGHT_DEATH`，终局再给精确死因；不把所有夜死伪装成“咬杀”，也不为兼容继续返回秘密旧字段。具体DTO与迁移规则由批准后的014定稿，不修改核心`whyDie`枚举。

### 技能数据转换的精确规则

- 令玩家数为N，技能值v：v=0不生成结果项；v>N时目标为v-N、球为黑，否则目标v、球为白。护卫沿用目标规范化但不显示球，不能因编码存在而新增球字段。
- 仅当前声称对应职业的玩家形成报告行；全局只遍历技能日`start <= day < gameDay`，若死亡则额外要求`day < deathDay`。空历史仍可能有行/破绽，不把“无可见结果”当成“此玩家没有真实技能”。
- 探针在当前日4、占卜者CO日3时仍实际显示技能日1/2；未CO的真实技能者不形成行。死亡日3的公开占卜者显示日1/2及破绽，不显示日3。
- 图形球缓存是另一种展示路径：`PlayerStatusRenderer`只缓存当前日-1结果，`renderSkillTargets:646—665`遍历缓存并按死亡日期过滤且跳过护卫图标；不能为了恢复缓存而把全部私有技能数组传给浏览器。文本报告已经支持可见既往历史，014以审计后的结构化历史提供必要数据即可。

### 怀疑摘要的精确规则

相邻当前日前三项分数差d按原实现：d<=2为`=`，2<d<=5为`≧`，5<d<=10为`>`，d>10为`≫`。不取绝对值、不改阈值、不把`=`承诺成原始分数严格相等。

只发送目标和比较类别，不发送d或任何分数。过滤零目标后保留原次序；空项不臆造目标或历史排名。核心选择排除死亡目标/自身（`SuspicionSystem:247—270`），但投影不自行重新排名。游戏日2即使内部已有数值也不开放摘要；终局界面不需要借此开放原始矩阵。

探针调用实际`createDoubt`得到了`= / ≧ / > / ≫`四类，文本中没有输入的原始100分；死亡观察者不出现。该探针绕过菜单直接验证文本，菜单日期门槛来自源码核验，不能声称对日期门槛做了交互实测。

## 终局、Replay与诊断的隔离

- `EndAnimeHandler:25—55`明确输出实际职业和精确死亡说明；`SettlementRevealProjector`只在FINISHED揭晓。允许终局给完整身份/精确死因，不代表进行中可提前下发；前端还须读完前置事件后展示揭晓。

- `UI.testBtn:340—359`是诊断按钮，点击向DebugLogger输出实际身份、精确死因和完整怀疑矩阵。**DebugLogger当前默认enabled=true**，投票页会注册该按钮，不能谎称它默认不可达；但这是诊断日志通道，不是常规公开信息面板。已批准v1安全规则明确排除这些秘密，本轮不把诊断输出作为扩大公开范围的依据，日志泄露治理仍归WEB-041/044。
