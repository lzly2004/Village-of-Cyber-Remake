# 2026-10-22：安全脚本误杀桌面进程及修复

## 责任与证据

故障由本助手新增的`tools/run-gradle-safe.sh`清理逻辑引入。此前声称“只终止本次子树”不成立；无Java残留更不能证明安全。用户本轮仅批准修复并隔离验证，未要求继续游戏开发。本轮不运行Gradle/浏览器，不调整锁屏、驱动、电源或系统内存配置。

旧逻辑：

```awk
{ parent[$1]=$2 }
END {
    owned[root]=1
    do { changed=0; for (pid in parent)
        if (!owned[pid] && owned[parent[pid]]) { owned[pid]=1; changed=1 }
    } while (changed)
    for (pid in owned) print pid
}
```

读取不存在的AWK数组项会创建空条目，末尾遍历所有键却不判断值。虚构输入`100 1 / 101 100 / 200 1 / 201 200`、root=100，应只输出100/101，实际还输出200/201/1。此复现只输出数字，没有发送信号。旧脚本将输出传给批量TERM/KILL，且EXIT trap在成功结束时也执行，可能终止权限允许的其他桌面程序，包括自己的监控与调用进程。

日志核验：

- 12:23:51：tracker、fcitx收到SIGTERM，同秒会话失联；对应定向构建结束。
- 12:56:47—48：tracker、fcitx收到SIGTERM，随后会话失联。
- 13:18:06.585：Gradle daemon-33931日志明确BUILD SUCCESSFUL in 40s并结束；同秒桌面程序收到SIGTERM、GNOME会话退出。

误选缺陷已经复现；它与三次退出时间及信号类型高度吻合，是高度可信的直接原因。没有系统调用审计记录，不冒充已捕获kill调用者的完整取证。不能仅凭“Fatal IO/Lost name”进一步断言是NVIDIA/自动锁屏；也不把上午六次真实OOM与本故障混为一谈。

## 修复边界

1. 删除旧ps/awk进程树扫描、批量kill、shell EXIT清理与监控后台进程；不是只在旧循环补一个过滤条件。
2. Bash入口exec一个Linux/Python标准库监护程序`guarded-process.py`，互斥锁留在监护程序，构建子进程不继承锁。
3. 监护程序启用并核验PR_SET_CHILD_SUBREAPER；父进程退出后，其后代（包括setsid另建会话者）由监护程序收养。系统不支持则拒绝启动构建。
4. 信号目标只来自内核给出的自身直接子进程列表；每次发送前用waitid(P_PID, WNOWAIT)再验证它是自身未回收的子进程。拒绝0、负PID、PID1、自身、父进程、非子进程和已退出目标。只给一个正PID发送信号，绝不向组发信号。
5. 单线程程序在验证和发送之间不回收子进程：其PID不能在这个窗口被其他进程重用。失去归属验证、子进程列表不可读时，不回退为全机扫描或批量终止。
6. 正常结束、SIGTERM/SIGINT和模拟低内存均走同一清理路径；先TERM，再仅对仍属自己的子进程KILL，收养/回收新产生的孤儿。清理有时间上限，不能确认清理完成则返回错误而不是宣称成功。

这不是硬cgroup隔离；不能捕获监护程序自身的SIGKILL，也不能保证清理无法退出的内核D状态任务。权限或环境不支持时失败关闭，不以牺牲桌面为兜底。Python使用系统3.8标准库，未安装第三方依赖。

## 验证

```sh
bash -n tools/run-gradle-safe.sh
python3 -B tools/tests/test_guarded_process.py -v
```

15项回归：

- 无信号复现旧AWK错误；拒绝特殊PID、模拟重用/非子进程PID、僵尸；仅向经验证的单个正PID发送信号（mock）。
- 低内存启动前拒绝、收养机制不支持时拒绝、子进程列表读取失败时不发送任何兜底信号。
- 正常/非零退出码保留；真实非子进程PID被内核归属检查拒绝。
- 正常父进程退出、SIGTERM、SIGINT、模拟运行中低内存；每个场景确实启动三层另建会话的无害Python进程，后代忽略TERM以覆盖KILL升级，结束后所有测试PID被回收。
- 每个隔离用例都有监护程序外部的兄弟哨兵，必须始终存活。Bash完整入口以/bin/true替代Gradle连续两次运行，验证锁释放和无关哨兵存活；未授权全量测试仍拒绝。

没有通过真实内存耗尽、真实桌面进程或真实JVM做破坏性试验。实际Gradle/Playwright退出路径仍需后续明确恢复验收，本轮不执行，也不将旧版本测试通过记录当作新监护程序的实机验收。
