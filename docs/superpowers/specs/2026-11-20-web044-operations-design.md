# WEB-044：安全运行诊断与健康检查

用户已明确调整顺序并要求继续开发044；050默认入口待统一交付，045未启动。本设计落实已批准的日志、健康检查、告警和游客终局降噪范围。

## 方案及边界

沿用现有WebDiagnostics固定枚举事件及stderr，在固定事件后增加UTC时间与固定严重度，便于故障定位；不增加日志框架或自由文本入口。不启用Caddy原始访问/运行日志，因为其可能包含能力URL；通过已有同源代理检查应用健康。外部监控平台与消息通知涉及账户/部署，不在本轮引入。

GET /api/v1/health 返回固定JSON：正常为200 {"status":"ok"}，停止或注册表回收连续状态异常为503 {"status":"unavailable"}。成功回收后恢复健康。接口受现有全局请求限额保护，无会话借用、续期、清理、创建或游戏命令；不返回身份、人数、ID、配置、版本、堆栈、路径。检查只代表HTTP进程已启动且回收任务未报告故障，不承诺所有对局、静态资源或物理音频正常。

提供Python标准库直接HTTP/TLS单次检查命令，默认回环HTTP端点；可检查已有localhost HTTPS代理。仅允许localhost/127.0.0.1，固定健康路径，无凭据/查询/片段；禁用环境代理、重定向，不关闭TLS验证。最多读取256字节，连接/握手/发送/响应头和正文共用1—30秒总网络时限（不包括本地CA配置加载）；只接受HTTP200及固定JSON对象。输出固定HEALTH_OK/HEALTH_FAILED/HEALTH_CHECK_REFUSED，退出0/1/2；不打印URL/异常/响应正文。由运维定时调用并按退出码告警；本轮不安装定时器、不发消息、不自动重启。

终局无正常逐局运行日志：继续关闭Web进程DebugLogger，录像录制保持工作；桌面日志策略不变。增加实际终局/关闭及恶意输入的日志负例，防止凭据和私有结果进入运行输出。
