# WEB-045：版本切换与浏览器历史保护

用户已批准开发045，并在完成后统一执行默认纯窗口入口、044和045的云端验证及试玩交付；不含Ready、合流、公网部署、系统设置或费用。

## 已确认目标与方案

采用既有发布ZIP校验和不可变版本目录，按相同origin显式停止旧服务、启动整套新版本；回退使用保留的整套旧版。与新增自动部署守护相比，此方案复用042/043，避免后台更新/强停/数据库迁移。没有新增录像、战绩或存储格式；不创建假自动迁移。

新增版本切换核对工具：外部可信SHA256校验旧/新ZIP后调用check_release；报告精确source及archive身份、标准化origin是否变化、旧局必失效、本地历史按origin保留、回退必须独立验证。准备模式将两份已校验快照解包到全新隔离目录，不覆盖版本/浏览器profile或启动/停止任何程序；失败保留自身新目录供诊断，不删除旧文件。

新增实际浏览器验收：同一浏览器context和固定HTTP origin，运行解包旧版A→新版B→后端重启B→回退A。每次只运行一个后端，使用既有guarded-process监护及自建子进程正常退出。预置一份有效录像、战绩与音量偏好，逐字段比较不变；活局在新后端请求404、UI明确提示失效且无自动POST，然后主动新开局得到不同凭据。检查能回放/切日及查看战绩；不重打一整局。现有043 HTTPS三种origin隔离测试继续保留，不把HTTP版本切换证明当公网TLS部署。

任意未来版本不能因本轮成功而自动标记数据兼容：升级前显式导出录像；当前战绩没有文件交换入口，需要额外灾备时由用户正常关闭浏览器后私下备份对应资料目录，不在运行中复制/修改IndexedDB；若存储格式发生变化，必须另做向后兼容/迁移评估。换域名、协议或端口为新origin：新页看不到原数据，回到旧origin原数据仍在，必要时显式导出/导入。服务端回退不能恢复已被浏览器删除的数据。

## 验收与交付

工具单测覆盖ZIP错误SHA/损坏、origin规范化/凭据拒绝、输出覆盖/软链拒绝、双版本隔离与输入漂移。相关工具测试纳入既有套件，不增加full套件编号或降低策略。先以现有两份真实发布包验证新启动命令；云端候选产物核对后，再以真实旧A和本轮官方B复验。

本轮不改生产Java/前端玩法；使用044已通过的本机693项证据，不机械再跑本机Java全量。最终精确head运行云端full24及发布包冒烟，下载核对官方artifact SHA/回执，准备同head试玩入口。下载并发沿既有逐轮约定，不在未批准时提高。Windows Data只读，保留bundle并报告未同步，不强改挂载。

用户验收包括：默认只有游戏窗口；Esc外围恢复；已有录像/战绩在刷新和服务重启后仍在；旧活局明确失效，可主动重开；44健康检查正常/停服/恢复。提供现成有效录像及逐步命令，不要求用户寻找存档或掌握部署操作。切版测试使用隔离验收资料，避免风险操作真实用户历史。
