# WEB-021：占位舞台、缩放与长列表布局

实现基线9056eef。021只建立占位舞台及可读、可操作的页面布局；没有接入原PNG/WAV、图像映射、图片转换或音频。正式单/多角色、死亡/处刑/结算视觉仍由023—025完成，素材预算沿用[020目录](web-asset-source-catalog.md)。A06/A07/A08不因占位交付而放行。

024接续：DAY_DIALOGUE/AFTERNOON_DIALOGUE已用[原事件立绘与背景](web-event-artwork.md)替换占位SVG；其他阶段仍保留占位，待025。下述等比缩放、原生阅读区、独立确认区和按事件重建约定继续适用。

## 舞台坐标与缩放

- 设计坐标**1280×720、16:9**，与桌面[UIConstants](../src/main/java/com/vocr/ui/UIConstants.java)的窗口基准相同。Web用[GameStage.vue](../web-client/src/GameStage.vue)的SVG viewBox和`xMidYMid meet`等比缩放，不宣称复刻当前Swing的动态布局实现。
- 舞台逻辑宽度为父容器100%，上限1280 CSS px，居中；按16:9计算高度。页面外层、标题、操作区和玩家区仍按浏览器文档流布局，页面允许垂直滚动，不承诺将整个对局UI压进一屏。
- 原型画面仅含背景色块、构图参考线和人形占位。只读取当前公开事件ch1/ch2/ch3的非空、非NONE键，去重后最多3个位置；wsw不放人物。位置采用居中间隔250设计像素的临时排列，**不表示已经按event_image_mapping选图或确定正式多图顺序**；024另行核对。编号标为“占位”，不冒充玩家编号或职业。
- 台词是原生DOM纯文本，不放进SVG/位图，不随艺术坐标做CSS transform。阅读区左右3%、底边4%，高度范围24%—46%；窄屏最高60%，超长文字在区内滚动。台词字号14—20 CSS px，保留换行/Unicode与019的独立异常诊断。
- 阅读区有命名region、`tabindex=0`、可见聚焦框及滚动说明，支持方向键/PageDown等原生滚动。确认/投票按钮在舞台外，避免被长文字滚动挤出。新事件从阅读区顶端显示：以已有确认游标和显示状态（事件/决策/终局）作为舞台实例键，为下一条事件或同游标下决策后的首条事件创建独立阅读区，避免继承旧容器的原生滚动动画；确认按钮在实例外，焦点与游标处理不变。阅读区局部设置`overflow-anchor: none`，迟后内容变化不触发其自动锚定补偿；同一事件的重新同步不重建该区域。没有按定时器自动确认、推进或生成额外存储。

本阶段电脑基线窗口为**1280×720**，推荐1440×900及以上；测试还覆盖1920×1080与1024×768窄窗口适配。默认回归保留原390px手机边界，但不提高为手机首发验收目标。125%/200%的本轮压力检查使用**CSS zoom**，不能当作浏览器工具栏缩放、不同DPI/系统缩放、所有浏览器或辅助技术已验收；046完成正式支持清单及原生缩放/键盘复检。

## 页面区域与列表

| 区域 | 布局及可访问入口 | 状态边界 |
|---|---|---|
| 舞台/确认区 | 宽舞台在上，阅读区内滚动，独立确认区在下 | 只改布局；事件呈现顺序、确认游标、刷新恢复、忙碌/未读/不确定禁用及终局读完才揭晓均沿用原条件 |
| 公开玩家列表 | 舞台下方自适应列，最小列宽170px；小屏单列；最高19rem，超长时内滚动 | 标题保留总人数；可见“列表内滚动/Tab/方向键”提示，命名region可聚焦，稳定滚动槽及滚动条样式；Tab仍可进入每个候补，不截获键盘，不产生额外写请求 |
| 个体预约 | 占卜/护卫两栏，1100px以下一栏；每栏显示公开行动者数量，一览最高26rem，区内滚动 | 仅消费服务合法公开行动者及候补，保持顺序和权威选择，不从素材或占位推断私有行动者 |
| 行动者行 | 原生details/summary，默认全部展开；summary保留人物、CO顺位、当前预约件数；候补fieldset两列，小屏单列 | Enter/Space展开/收起，Tab进入可用候补；浏览不写入、不动游标；fieldset仍使用原canDecide禁用条件；折叠是DOM浏览状态，刷新默认重开，不存sessionStorage |
| 公开信息/历史 | 继续在原公开条件下显示，位置跟随上方区域 | 不建立历史快照回滚，不改变最新公开聚合状态与逐事件叙事的既有差异 |

19rem/26rem是阅读窗口高度，不是玩家/行动者/候补数量上限。全部条目仍保留在DOM中，滚动或折叠即可访问；无虚拟列表、删条目、重排或按角色过滤。真实投票/询问/预约及409/失响应恢复继续走原事件处理函数，布局没有复制业务规则。
