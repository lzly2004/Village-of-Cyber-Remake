# 审查规范

本文件适用于 coder 与外部 reviewer；授权、工作区保护和验证门槛以根目录 AGENTS.md 为准。

## 通用要求

1. 明确基线、目标提交与实际审查范围。默认审查上次 review 之后的新提交；未知基线时先说明，不假定本地跟踪分支等于远端最新状态。
2. 优先检查规则、信息边界、持久化兼容、并发与恢复，再检查维护性。功能、修复、文档和重构采用与其风险相称的证据，不以净行数评价功能正确性。
3. 每条发现包含严重度、文件位置、触发条件、可观察后果和证据；明确区分实跑结果、源码推断和待作者确认。无法构建或未执行的检查必须如实标注。
4. 输出依次包含阻断/非阻断发现、已验证声明、开放问题。不必重复所有实现细节；没有发现问题不等于证明没有风险。
5. Reviewer 不修改共享工作区的跟踪文件，不暂存、提交或推送。临时探针、负例与父版本构建在隔离目录执行，避免污染桌面数据、黄金摘要或用户修改。
6. Coder 逐项核验并归档报告要点、证据与处置。合理反驳应记录理由；延期项必须指定任务。构建通过不能取代对具体行为问题的复现。

## 重构/收口专项

仅对声称“不改变行为”的重构或收口追加以下要求，不强行套用到新增功能或预期改变行为的修复：

- 对比父提交与目标提交的生产代码增删、职责与调用链。行数只是维护成本线索；净减少、持平或增加都不能单独证明质量。
- 父/子版本使用相同工具链、配置、资源、种子及输入策略执行测试；记录输出差异和实际执行条件。
- 黄金摘要相同是相应覆盖范围内的回归证据，不是全局行为等价证明。摘要变化必须定位到事件/状态字段；不能仅凭终局、天数或随机调用次数相同，就断定只有格式变化。
- 父版本也失败时，区分既有问题与新增回归，不能将失败直接豁免。资源与概率校验须核对实际内容、映射和加载路径，不能只比数量。
- 不为通过验收而刷新黄金摘要；涉及规则或兼容性变化时遵循 AGENTS.md 的额外授权要求。

本规范吸收了本地未跟踪重构 skill 的证据优先与父/子对照思路，但不将该用户文件自动纳入提交，也不将其特定历史样例和本机命令变成共同约束。
