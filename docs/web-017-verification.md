## 2. 版本化验收方式

`Web017JourneyTest`固定基线种子jianyi4201、tongchang4202、yaoohu4203、kuangxin4204、beide4205、maoyou4206、daxing4207。每配役分别执行指定到底与混合控制两条完整流程，再增加通常村真实CO中断分支。

1. 应用直连使用原SeededGuestSession固定种子；真实HTTP使用测试专用createReleaseBaseline，在start消耗随机数前按配役设置同一基线。生产HTTP没有seed参数，生产runWeb没有固定种子。
2. 每条命令通过应用实际执行，再提交同一HTTP请求，逐字段比较完整JSON响应，并以GuestWireContract检查形状/值级秘密门禁；每步全量GET再与应用当前快照比较。
3. 输出`build/web017/<配役>-<策略>.json`：仅公开初始快照、命令体、响应与全量重读期望，约4.6MiB合计，不含sessionId或核心对象。它是本轮运行生成的临时对照，不是新的黄金摘要，不提交或进入生产/桌面产物。
4. 每份临时文件含main/test/web全部Java源码路径及字节的SHA-256指纹。Playwright入口重新计算，缺文件/指纹不同即失败；不能拿旧产物验证新源码。更新源码后重跑应用/HTTP生成阶段，不能手改JSON绕过断言。
5. `playwright.gate.config.js`独立于默认55项，测试源集启动器参数为`--args="17071 --release-baseline"`；监听仍是127.0.0.1，走原安全监护、单worker/retries0。默认测试入口仍为原4202，另作55项回归。
6. 浏览器的每次游戏写入都由页面按钮/复选框触发，不借request API代替UI推进。逐一比较实际请求体、响应与对照文件，再以真实GET比对全量状态；读取API只用于核验。对局创建/最终释放不计入策略命令数。

### 固定操作策略

- 每条命令前逐条确认全部presentedEvents，核对人物参数与最后游标；不跳过CO中断的下午发言。读完才能继续写，终局未读时不显示真实身份/公开信息面板。
- 指定策略：按公开玩家列表选第一个存活且非共有CO者，清理旧目标、选择新目标、用权威完整有序DESIGNATED候补投票，最多80次策略循环；一直执行至终局，不替换为FREE。
- 混合策略：初日反序两人CO询问→五种职业CO询问→回避关/开→两种全体技能预约/取消/恢复→有公开行动者时个体取消/恢复→全体取消；随后按FREE/GREY/DESIGNATED轮转到终局。GREY无合法动作才回退FREE，但终局断言必须真实执行过三种方式，不能靠回退声称覆盖。
- 妖狐4203的公开护卫者缺席有显式前提断言，其余六配役必须真实执行个体护卫；所有七配役必须真实执行个体占卜。缺席不是“测试未执行也算通过”，该分支只能对对应合法空态标不适用。
- 每次已完成票型都断言非最终轮同票、末轮唯一首位、轮号连续、轮数不超过现有MAX_VOTE_ROUNDS=3；常量变化会要求重新核对桌面硬编码1/2/3分页，不默默刷新预期。没有修改既有末轮无限重掷候选CORE-TIE-001。
- 独立中断流程：通常4202公开目标9，指定投票必须返回voteCompleted=false、AFTERNOON_DIALOGUE、同日且完成票型不变。该分支刻意不投到终局；其他14局必须全部结束。
- 每局首次出现完成历史后刷新：游标/会话存储不变、无新增写入、历史/公开状态重建；终局再刷新检查揭晓。访问debug/context/recorder/suspicion路径必须404。
