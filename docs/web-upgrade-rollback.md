# WEB-045：升级、重启、回退与浏览器历史保护

## 本轮做了什么

沿用042的版本ZIP和043的同源托管，新增版本切换核对/准备工具及真实浏览器验收。不会自动部署、停止服务、改浏览器资料、迁移数据库或清理旧版本。没有新增Replay/战绩格式、生产依赖或玩法改动。

版本ZIP必须来自可信发布渠道，先核对GitHub官方run/head/attempt、artifact id和digest，再使用已核验的包内`vocr-web.zip`SHA。ZIP自校验或任意JSON都不能证明来源。

## 切换之前

1. 记下原版完整source SHA、ZIP SHA、正式origin（协议+主机+端口）、当前运行目录。保留原ZIP和后端/前端整套版本，不能只保留旧页面。
2. 提前通知：服务重启会使进行中的游客对局失效；不会恢复或重放未确认命令。浏览器中的已保存录像、战绩与音量不依赖这个内存对局。
3. 从Replay页显式导出重要录像，并核对文件可读。**当前战绩页没有战绩文件导出/导入入口**；不要使用不存在的按钮。需要额外灾备时，由用户正常关闭浏览器后私下备份相应浏览器资料目录，不在运行中复制/改写IndexedDB，不把完整profile（可能含凭据和其他隐私）上传为证据。本工具不执行profile备份。
4. 本轮没有修改存储schema，但不承诺任意未来版本能退回旧版：将来涉及存储升级时，要先验证向后兼容/迁移并另定回退方案。服务端回退不能找回已被浏览器清除的数据。

## 核对并准备独立目录

以下是运维模板；用户日常试玩无需执行此段，也不要填写来历不明的digest：

```sh
python3 -B tools/prepare-web-upgrade.py \
  --current /absolute/old/vocr-web.zip --current-sha256 OLD_OFFICIAL_ZIP_SHA256 \
  --candidate /absolute/new/vocr-web.zip --candidate-sha256 NEW_OFFICIAL_ZIP_SHA256 \
  --current-origin https://localhost:18443 \
  --output /absolute/new-private-transition
```

只接受全新无软链输出，先复制到自己的临时快照、核对外部SHA、检查完整发布契约，再解包为`current/`与`candidate/`，并写`transition-plan.json`。源文件在快照之后被替换不会改变已核验版本；SHA错误或坏包在输出创建前拒绝。不覆盖已有输出；后续磁盘/权限失败可能留下本工具新建的部分目录，需诊断后换一个新输出，不删除原版本。

如计划改变origin，显式补`--candidate-origin`。工具按浏览器常见origin规则规范大小写/默认端口，拒绝不规范数字IPv4别名。报告总是写明`browser_data_automatically_migrated=false`及回退兼容`UNPROVEN_UNTIL_PAIR_ACCEPTANCE`，不能把准备成功当作升级验收通过。

## 逐步升级与回退（仅运维）

1. 按原服务所属终端/服务管理方式正常停止旧前端及后端，等到退出、端口释放。不要强杀未知进程，不同时运行两个版本抢占端口。
2. 用已有`host-web.py prepare --frontend <candidate/frontend> --output <new-private-host>`准备对应版本的托管目录；后端用该版本`candidate/backend/run.sh 17075`启动。Caddy按043流程启动，浏览器访问原origin。前后端必须成套切换。
3. 使用044的`check-web-health.py`检查后端/代理就绪，再检查静态入口。localhost隔离证书必须按043规则验证本次CA，不能全局忽略TLS错误；正式证书、服务管理器、公网监听仍待部署授权。
4. 原浏览器中刷新：旧局应404 GAME_NOT_FOUND并显示明确失效提示，不自动POST，不错误恢复旧凭据。主动重新选配役应创建新局。核对原录像/槽位/战绩及音量未变；Replay切日和战绩查看仍可用。
5. 如需回退，正常停止新版本，按相同origin启动保留的`current/`整套版本，重复健康、旧局失效、新局创建和历史核对。不删库、不清浏览器站点数据来掩盖不兼容。
6. 换域名、HTTP→HTTPS或端口意味着新origin，新页不会自动看到原历史；返回旧origin时原历史应仍在。必要迁移使用已有录像导出/导入；战绩没有自动迁移入口，不假称数据已搬家或被删除。

## 自动化验收的精确范围

`tools/upgrade-smoke.py`接收同样的旧/新ZIP+官方SHA，输出必须位于本仓库`build/`内的新目录。它使用两套真实解包前后端、同一个隔离浏览器context、固定`http://127.0.0.1:5180`，串行执行A→B→重启B→回退A。每次正常停止自己创建的受监护子进程，不扫描/结束用户进程；每次后端执行仍有2GiB监护。它不使用真实用户profile。

测试导入有效旧录像，建立一条已知战绩和音量偏好，比较IndexedDB所有现有stores、DB版本和音量原文；每次确认旧凭据真实404、UI清除失效凭据、没有自动开局、用户主动可开不同新局，并实际打开战绩、回放及切日。不会将Replay导入加成战绩，也不会因为只比较空库而声称历史保护通过。

版本切换证据绑定两包SHA与source。此前c9f5db2→f754a07的真实包演练已通过；本轮官方新包尚未生成时不能将演练冒充最终B通过。新包下载后必须再跑旧A→本轮官方B。现有043真实Caddy三类origin隔离继续验证；本轮新增044健康接口通过TLS代理，缓存指令可由代理/后端重复设置，但唯一指令必须是no-store。

full24包含工具单测及真实hosting套件；**不会自动执行任意历史包对的升级验收**，后者作为本轮官方产物下载后的独立交付证据。HTTP包切换也不代表公网TLS、正式浏览器/DPI或通知系统已部署。

## 用户最终怎样验收

交付目录会提供`start.sh`、现成`Replay测试用录像.json`、`验收步骤.md`和健康检查命令。新候选使用专用浏览器资料目录，第一次可能看不到旧候选历史，这种开发期隔离不等于网站升级丢数据；不要覆盖原存档来测试。

1. 启动本轮候选，首次核对官方身份后输入CONFIRM。默认应只有居中的游戏窗口；Esc恢复外围，点原按钮再次隐藏，刷新又默认纯窗口。
2. 主菜单进入Replay，点`録画ファイル読込`，选择提供的测试文件，选空槽、确认内容并写入。播放、切日、返回，左上成功提示不应残留。
3. 记下槽位、战绩总局数和音量。若本轮专用资料尚无战绩，0局是正常的；非空账本保护已自动验证。如要亲自验非空战绩，可正常完成一局后记数，无需连续重玩多局。
4. 刷新后再次查看。然后在启动终端Ctrl+C正常停服务，健康检查应失败；正常关闭该专用浏览器，等待退出，再用**同一条本轮start.sh**重开。不要切到旧候选、不要删锁/站点数据。录像、槽位、战绩和音量应保持，健康检查恢复成功。
5. 正常新开一局确认可操作，不期待原活局跨服务重启恢复。旧凭据404及页面失效提示已由隔离浏览器自动验收，不要求你手动结束后端进程来触发。

如启动器报告端口/PROFILE_IN_USE/低内存，保留原提示并反馈；不自动清锁、强杀或降低门槛。最终交付必须附实际可用的启动命令，不能仅给模板。
