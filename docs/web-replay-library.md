## 读取与信息边界

`GET /api/v1/games/{id}/replay?eventCursor=N`只读返回UTF-8 JSON九槽数组：0号槽为既有`ReplaySave.fromRecords`生成的v3，其余null。不加sessionId、revision或本地数据库ID，不直接序列化recorder/context。响应沿用no-store；服务器不写Replay/战绩文件。

- eventCursor必填、单值、非负十进制整数；错误400 INVALID_REQUEST。未知/释放/重启丢失会话404 GAME_NOT_FOUND；进行中/关闭状态409 INVALID_STATE。FINISHED且游标恰等于发布末尾才可读，否则400；不重置游标、不确认事件、不推进revision。
- 这里的确认游标是持凭据客户端的声明，不是服务器证明用户实际读过文本；网页只有完成全部事件且非busy/uncertain才请求。不能据此宣称已有039的公网凭据安全。
- 应用锁内只拿031冻结的不可变副本，解析/序列化在锁外，不调用持锁磁盘I/O的saveDesktopReplay。与释放并发时按快照取得先后线性化；不会返回在途秘密。
- 最大20000条、每条UTF-8 64KiB、记录合计及最终文件8MiB；最大50日快照。超限413 REPLAY_LIMIT，不截断；终局数据缺失/未完409 REPLAY_UNAVAILABLE。浏览器另以流累计8MiB、严格UTF-8/JSON/v3结构校验，HTML伪200不当成功。
- 浏览器校验已知字段/安全整数/正常枚举/日期及玩家唯一/稳定索引/票型、技能边界/汇总，保留rawRecords原文、多行、Unicode及大seed字符串。不会split换行或改两类候补索引。总天数遵循Java的max(END日,最大快照日)，不强制二者相同。不在032重解析/重建全部rawRecords业务语义；历史文件完整导入校验仍归035。

## 本地事务与交互

库名vocr.replays.v1，IndexedDB schema=1，recordings以内容SHA-256为key。内部元数据为id/savedAt/bytes/replay，不混入交换文件。ID从已校验的v3语义内容计算，排除saveTime和两个派生显示缓存，保留所有数组顺序；同局重新读取即使保存时间不同也提示已存在、不覆盖旧件。ID不是会话凭据，不累计战绩。

最多9局/录像JSON合计64MiB（不含IndexedDB内部开销，浏览器实际配额可更低）；保存前校验全库结构/字节数/内容hash。hash异步验证在只读事务外完成，再在readwrite事务内比对完整快照；跨标签竞争只对尚未写入的本地事务做最多5次重新核验，持续冲突明确LIBRARY_CHANGED。不重试游戏写命令/网络读取，不用localStorage降级或先改内存后猜成功。

只有事务complete才报告保存/删除成功。add/配额异常整笔abort、旧数据不改；打开/事务15s有界，拒绝/blocked/超时/坏库/hash不符明确诊断、不重建/清库。事务已提交但随后刷新列表失败时用户应重新读取列表确认；再保存通过内容去重。浏览器清数据、私密模式和换origin可丢失/隔离此库，页面明示；不是永久备份承诺。

列表显式打开才读库，启动不预取录像；查询按日期/配役/胜败过滤，详情只展示来源汇总/容量，不提前实现播放或技能。删除需逐条确认，可取消，只删选中本地ID；跨标签刷新通过显式“一覧を再読込”。库在大厅、会话失效或释放后仍可读；不把旧录像恢复成进行中对局。保存的晚到响应在session/cursor/eligibility变化时丢弃，不影响对局操作。所有内容为纯文本，不用v-html。IndexedDB对象本身的属性访问也在捕获范围，拒绝能力不影响App启动/开局。

配额失败后已有库保留，可删不需要的录像再显式重试；服务端当前终局须尚可读。文件下载救援、迁移和真实双向交换尚未提供，归035；本轮不宣称已实现030所列“失败可导出”的完整首发能力。不要在尚未保存成功时释放当前临时会话。
